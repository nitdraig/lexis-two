## Implementation Notes
- Specxis caps a spec at 10 tasks and sets no minimum. Tasks here are grouped by concern on purpose (`fix-specx` proposes making that the rule).
- The split between `desx` and `slopx` is by reason, not by file type. Rule of thumb for later additions: a defect even when a person made it goes to `desx`; a default-looking choice a brand could make on purpose goes to `slopx` as advisory.
- Order: 001 proves the core; 002 adds copy; 003 wires in the existing desx detector and exports its helpers; 004 grows both rule sets (the `desx/*` additions are additive after `fix-desx`: the detector now has tests and a stable report format); the skill (005) comes after all passes so its text matches the registry; 006 reuses the registry's `immediate` tier; 007 and 008 last.
- The positioning change touches wording that `fix-desx` shipped (skill description and docs). It changes words only, not behavior.
- Rule counts: tier 1 has 30 rows (32 rule ids, since one row covers three desx scale rules) and tier 2 has 21 rows. Tier 1 is the commitment; tier 2 is delivered as far as calibration shows low noise, and unfinished rows stay in the doc as backlog instead of being half-built. Ids by owner: `code/*` 5, `copy/*` 10, `look/*` 6, `desx/*` 10 ids (3 new), plus `slopx/waiver-without-reason`, in tier 1.
- Known baseline in this repo, measured before any code: 35 `console.log/debug` in 9 files, all CLI scripts (hence the convention-aware debug rule); 7 intentional one-line empty catches; emoji only in `README.md` and a generated benchmark JSON; no `_unused`, `@deprecated` or TODO in JS/TS. After `fix-desx`, a dry run of the design detector on this repo gives 9 type-hierarchy findings, 0 nesting and 0 contrast.
- This repo's Markdown uses em dashes widely, so prose rules stay behind `--prose` and the calibration run does not use it. UI strings in `site/src/i18n` are the real copy target here.
- Impeccable is optional and third party. The rule ideas come from its public catalog and docs; no code or text was copied. `handoff` names a command; the invocation syntax per host was not verified.
- Claude Code facts verified from its hooks documentation: PostToolUse `additionalContext` adds context without blocking, `Edit|Write|MultiEdit` is an exact-list matcher. Not verified: Stop-hook output and `stop_hook_active`.
- `git diff -U0` gives the new line numbers in the `@@ -a,b +c,d @@` hunk header. Renamed and binary files must be skipped without crashing.
- Emoji rule: `\p{Emoji_Presentation}` or any character followed by U+FE0F; plain `\p{Extended_Pictographic}` would flag `(c)`, `(r)`, `(tm)` and common dingbats.

- Deviations from the spec text, on purpose:
  - `fileLevel` is true when the flagged line is not part of the change (for `look` and `quality`), not for every finding of those passes.
  - `slopx-disable` with no suffix waives the whole file, as Impeccable does; `-line` and `-next-line` are the line forms.
  - In `.slopx.json`, `ignoreRules` and `ignoreFiles` entries are objects (`{ rule, reason }`, `{ glob, reason }`), so every ignore carries a reason.
  - The repository now has its own `.slopx.json` that ignores `scripts/slopx-rules.js`, `tests/slopx-*.test.js` and `docs/slopx.md`, which contain the patterns they detect.
