framework de orquestación de agentes de código

El agente hace el loop. Vos aprobás cada vuelta.

Lexis-Two coordina agentes especializados —planificación, implementación, revisión, seguridad— en un loop de trabajo real: descubrir, especificar, construir, revisar. Nada avanza a la siguiente vuelta sin que lo confirmes vos.

El loop corre solo entre etapas. En build, se detiene y espera tu aprobación por tarea.

el problema

Dos extremos, ningún término medio

Hoy elegís entre prompt a prompt (lento, control total) o un agente autónomo suelto en tu repo (rápido, sin frenos). Lexis-Two es el punto intermedio: loop estructurado, con un humano que decide si la vuelta siguiente se ejecuta.

Agente 100% autónomo

Sobre-construye, agrega abstracciones que nadie pidió y avanza varios pasos antes de que notes que se fue por las ramas. El costo de revertir crece con cada vuelta sin control.

Loop con gate humano

El agente ejecuta una tarea, se detiene, mostrás el diff, aprobás o corregís. La siguiente vuelta arranca recién ahí. Velocidad de agente, criterio humano.

cómo funciona

Un loop de cuatro etapas, con freno de mano incorporado

Cada etapa es un comando. El loop las encadena; el gate humano decide si sigue.

01

Descubrir /discx

Define el MVP, prioridades y límites antes de tocar código. Sin esto, no hay spec que valga.

02

Especificar /specx plan

Convierte la propuesta en spec.md (MUST/SHOULD/MAY) y una lista de tareas atómicas, una por archivo o función.

03

Construir /specx implement

Implementa exactamente una tarea de la lista. Se detiene. Vos revisás el diff antes de que siga con la próxima.

⏸ espera tu OK
04

Revisar /lexis review · /desx

Evalúa el diff contra la spec, busca sobre-ingeniería y desliz visual. Vos cerrás o mandás otra vuelta.

01

Descubrir /discx

Igual que en el modo con humano: define el MVP antes de especificar.

02

Especificar /specx plan

Genera spec y tareas sin pausa para confirmación intermedia.

03

Construir todas las tareas

Ejecuta la lista completa en una corrida, pensado para lotes chicos y bien acotados por Discovery.

sin pausa
04

Revisar al final /lexis audit

Una sola revisión sobre todo el lote antes de cerrar. Más rápido; menos puntos de corte.

el equipo

No es un agente. Es un equipo con roles fijos

Cada rol tiene un permiso explícito. Los auditores son de solo lectura por diseño: no pueden tocar código, solo señalarlo.

lexis-one escribe

Agente principal

Implementa, edita, corre bash. El que hace el trabajo dentro del gate.

lexis-review solo lectura

Revisor estratégico

Evalúa cambios contra la spec. Nunca edita.

ui-architect solo lectura

Arquitecto UX/UI

Asesora sobre diseño. No implementa — deja la decisión final en manos humanas.

refactor-agent escribe

Especialista en refactor

Reestructuración de código a gran escala, siempre dentro de una tarea acotada.

security-auditor solo lectura

Analista de seguridad

Corre herramientas de auditoría. Reporta, no corrige.

design-auditor solo lectura

Desliz visual + tokens

Detecta UI genérica de IA. Solo puede escribir DESIGN-AUDIT.md.

por qué el loop no se dispara solo

Disciplina de ingeniería en cada vuelta

La simplicidad acá es método, no estética. Antes de escribir código, el agente para en el primer escalón que se sostenga.

YAGNI

Cuestiona cada feature y abstracción antes de que exista.

KISS

Stdlib y APIs nativas antes que una dependencia nueva.

DRY

Un solo catálogo de skills; los adaptadores enrutan, no bifurcan lógica.

SOLID

Límites de módulo claros — ninguna abstracción que nadie pidió.
